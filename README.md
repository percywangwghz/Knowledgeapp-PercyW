# 一级投研知识库

面向一级市场投资研究的**结构化 Markdown 知识库 + AI 研究工作台**（Streamlit 单机应用）。

它不止是一个文档浏览器：信息采集（公众号/网页）、AI 整理归档、项目评审、观点压力测试、
行业认知反哺沉淀，全部在同一个闭环里完成——而且**所有 AI 写回知识库的动作都必须经过
人工预览确认**，机器永远不擅自改你的文档。

## 功能总览

| 模块 | 入口 | 干什么 |
|------|------|--------|
| 知识浏览 | 侧边栏 KNOWLEDGE / 首页 | 九个分类浏览、全文搜索、面包屑回跳、目录跟随、Zen 禅读模式 |
| 文件归档 | 顶栏「文件归档」 | 拖入 PDF/DOCX/TXT/MD，AI 读取内容、提议分类并整理成结构化文档，人工改判后入库 |
| 投资雷达 | 顶栏「投资雷达」 | 信源抓取 → AI 提炼信号 → 聚成主题叙事 → 跟踪边际变量 → 定期生成周报；六子页：总览/信号/主题/变量/周报/来源 |
| 公众号技术提取 | 雷达「来源」页 | 粘贴公众号文章链接，AI 抽取技术要点，沉淀为「技术沉淀」档案 |
| 新项目评审 | 顶栏「新项目评审」 | 五步流程：选项目 → 选行业上下文 → AI 对照既有认知做增量评估 → 人工修订 → diff 预览后写回 |
| 论文之战 | 顶栏「论文之战」 | 选一篇观点文档，AI 红队按「假设攻击 → 证伪 → 反世界 → 评估」四步方法论发起多轮压力测试；结束后生成写回预览，确认后把假设状态/证伪条件/置信度沉淀回文档 |
| 任务抽屉 | 顶栏「任务」 | 所有后台任务（抓取/提取/评审/归档/Battle）的实时进度中枢：进度条 + 当前步骤 + 已用时/预计剩余，3 秒自刷 |
| 静态导出 | 命令行 `python build_html.py` | 把整个知识库导出成纯静态 HTML 站（`dist/`），可任意托管 |

## 快速开始（本地）

**Windows**：双击 `start.bat`（首次运行自动建虚拟环境 + 装依赖，约 1-3 分钟）。

**macOS / Linux**（或手动方式）：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/streamlit run app.py
```

浏览器自动打开 `http://localhost:8501`。要求 Python 3.10+。详见 [部署说明.md](部署说明.md)。

## API Key 与模型

AI 功能需要你自己的大模型 API Key：打开页面后在**左侧边栏「设置 / API」**粘贴。

- 内置厂家预设：Moonshot（默认）/ DeepSeek / 智谱 / 豆包 / 阿里百炼 / Anthropic /
  自定义 OpenAI 兼容端点，模型名可改
- Key 只保存在你自己机器（`data/local_api_key.txt`），随 `.gitignore` 排除，不会上传
- 不填 Key 也能正常浏览所有文档，只是 AI 功能不可用
- 命令行直跑脚本（`radar_auto.py` 等）时，key 读取顺序：
  环境变量 `MOONSHOT_API_KEY` > `~/.kimi/config.toml`

**PDF 高保真解析需配置多模态模型**（如 kimi-k2.6 / qwen-vl-max / glm-4.6v / gpt-4o 等）：
配置后 PDF 逐块渲染成图、走你的 API 转录为 Markdown（表格/标题/图表解读/公式齐全）；
模型不支持视觉或未填 Key 时自动落本地库链（pymupdf4llm → pdfplumber → pypdf），
纯文字 PDF 也能入库，扫描件与复杂版面会降质。详见 `skills/pdf-preprocess/SKILL.md`。

## 知识库目录

应用启动时自动读取**应用所在目录下的 `knowledge/` 文件夹**，解压即用，无需配置。

| 目录 | 分类 | 内容 |
|------|------|------|
| `01_industry` | 行业认知 | 赛道全景、产业链、投资逻辑 |
| `02_deals` | 项目解剖 | 公司深度、投资假设、风险分析 |
| `03_frameworks` | 方法论 | 评估框架、分析模板（本仓库已含全部框架文档） |
| `04_comparables` | 横向比较 | 项目矩阵、竞品对照 |
| `05_tracking` | 动态追踪 | 追踪表、周报 |
| `06_strategy` | 投资策略 | 产业链图谱、主题策略 |
| `07_learnings` | 经验沉淀 | 方法论总结、案例复盘 |
| `08_funds` | 被投基金 | GP 方法论、投资逻辑拆解 |
| `09_tech` | 技术沉淀 | 技术档案；公众号技术提取自动落入 |

归档、技术提取、周报等功能产出的文档会自动写入对应分类目录。
路径解析顺序（高级）：环境变量 `KB_KNOWLEDGE_DIR` > 应用目录下 `knowledge/` > `~/.kimi/knowledge`。

## 数据与安全

- **知识库 = 包内 `knowledge/` 文件夹**，纯 Markdown，拷走整个文件夹即完整备份
- **写回必审批**：Battle 沉淀、评审反哺、归档入库等所有 AI 写操作，一律先生成预览，
  人工确认后才落盘；预览丢弃不影响任何现有内容
- **`data/` 是本机运行状态**（API key、任务进度、会话记录、索引缓存），已在 `.gitignore`
  排除，不要提交；删掉只会丢失任务历史和设置，不影响知识库本身
- 本仓库只放框架与代码；私人的项目/基金研究内容不要传上来

## 项目结构

```
app.py            主应用：路由 / 布局 / 首页 / 阅读页 / 搜索 / 任务抽屉
battle.py         论文之战（三栏辩论室 + 写回审批）
radar.py          投资雷达六个子页；radar_auto.py / radar_wechat.py 为抓取脚本
review.py         新项目评审（五步流程 + diff 写回）
ingest.py         文件归档流水线
tech.py           公众号技术提取
jobs.py           后台任务状态统一读取（任务抽屉数据源）
llm.py            多厂家 LLM 调用层（key/模型/base_url 四级注入）
indexer.py        知识库索引构建；mdblocks.py Markdown 块工具；tracks.py 赛道识别
build_html.py     静态站导出（→ dist/）
config.py         路径、分类、厂家预设
skills/           PDF 预处理等技能说明
docs/             前端设计说明书 v2、前端手册、改造方案
```
